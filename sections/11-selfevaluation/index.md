# Self-evaluation

## Martina Fava

Within the BridgeIT project, my main role was **Data and API developer**, focusing mainly on the persistence layer, FastAPI backend, frontend integration, testing, and project infrastructure. I implemented the repository abstraction and SQLite persistence, the main requirement-related API endpoints and the common `ApiError` handling, and I also developed the basic frontend flows for creating and viewing requirements. During the development, I also worked on API and persistence tests, code quality checks, Docker support, CI/CD and the semantic-release process. In particular, I had to diagnose and fix issues in the release pipeline related to the GitHub token and conditional PyPI publishing, which gave me a better understanding of automated versioning and software delivery. I also contributed substantially to the **documentation**, drafting and revising major sections of the final report, including Requirements, Design, Validation and Release, and keeping them consistent with the actual state of the artifact. From my perspective, one of the main strengths of BridgeIT is its clear separation of concerns, which keeps the domain logic independent from persistence, API and AI components. The Human-in-the-Loop approach is another important strength, as AI supports the analysis without making the final decision on a requirement. The main limitations are the missing traceability and derived artifacts functionality, the absence of authentication and authorization, and the lack of a complete automated end-to-end test. Overall, this project allowed me to improve my development, debugging and code review skills, while gaining more practical experience with Git, GitHub, Docker, CI/CD and automated release management. It also helped me understand how implementation, testing and documentation need to evolve together to maintain a consistent final product.

## Nicole Tresca

Within the BridgeIT project, my main contribution focused on the **domain model, AI-assisted requirement workflow, validation, and final project integration**. I implemented the initial `Requirement` aggregate root and its value objects, including the lifecycle rules and valid state transitions, and later contributed to the AI Gateway and to the analyse/validate workflow that connects AI-assisted requirement analysis with explicit human validation. I also worked on improving the frontend interaction by introducing clearer validation and error feedback and by verifying that invalid lifecycle operations were correctly rejected by the backend.

Another relevant part of my work concerned **testing, release management, and final validation**. I contributed to diagnosing and fixing the semantic-release pipeline, including the release baseline and automated versioning workflow, and I carried out and documented the manual end-to-end acceptance tests covering approval, editing, rejection, re-analysis after clarification, repeated refinement cycles, and invalid state transitions. This work helped me better understand the importance of validating not only individual components but also the consistency of the complete user workflow.

I also contributed extensively to the **final documentation and project review**, including the User Guide, validation evidence, repository README files, project scope clarification, and consistency checks between the report and the implemented artifact. One of the main strengths I see in BridgeIT is the explicit separation between probabilistic AI assistance and deterministic domain rules: the AI can identify possible quality issues, but only an explicit human decision can produce an authoritative outcome. At the same time, the project still has clear limitations, including the absence of authentication, persistent AI-analysis history, traceability links, derived artifacts, and a fully automated end-to-end test. Overall, the project strengthened my understanding of Domain-Driven Design, Hexagonal Architecture, automated testing, Git/GitHub workflows, CI/CD, release management, and the importance of maintaining alignment between requirements, implementation, validation, and documentation throughout a software project.
